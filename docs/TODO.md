# IBKR AI 助手：开发任务与验收

状态：Agent/产品存储、聊天通信和 Apple 客户端首版已完成本机验收；IBKR paper/live 只读配置与适配层已完成离线验证。真实模型、真机、外网、Gateway 和券商验收仍未完成，以下任务按边界继续跟踪。

## 1. 当前顺序与交付目标

按用户最新安排，当前先做 **M1 的 Agent/产品存储与聊天 → M5 的客户端/通信基础**。Agent 已选 PydanticAI Core＋官方 Harness；不再重新选型。IBKR 只读与对账仍独立推进，不把研究/记忆运行时作为其前置条件。

本轮已交付：Mac 后台聊天 API、持久会话、明确演示模式、Apple 通信 SDK/客户端与增量同步；真实模型、iOS 真机和外网需要分别验收。后续券商交付继续验证指定模拟账户只读、官方端操作同步及重连对账，订单提交保持关闭。

| 阶段 | 交付与依赖 |
| --- | --- |
| M0 接入准备 | 固定环境、范围和验证证据；先联调薄服务路线。 |
| M1 基础与聊天 | 先实现交易服务、领域模型、存储和权限基础；会话、Agent、SwiftUI 随后补齐。 |
| M2 只读与对账 | 依赖券商准备与必要存储；聊天查询 M2-09 可后置。 |
| M3 审核与模拟订单 | 依赖 M1/M2；审核、授权、风控和未知结果恢复。 |
| M4 定时订单 | 依赖 M3；任务持久化、到点重审、窗口和恢复语义。 |
| M5 iOS 与提醒 | 安全远程访问、会话同步、价格监控和通知。 |
| M6 部署与实盘门槛 | 运维、备份和故障验收；相关场景通过后明确实盘开放范围。 |
| M7 后续扩展 | 单腿/高级期权、可选研究工具，按需求单独验收。 |

## 2. M0：环境与 IBKR 接入准备

- [ ] **M0-01 首版范围**：确定账户/市场及支持矩阵；首批建议股票限价单，明确卖空、零股、盘前盘后与 TIF 边界。
- [ ] **M0-02 风险参数**：确定金额、敞口/集中度、当日限额、报价偏离及数据有效期，区分拒绝与补充信息；未定参数阻止提交，不阻塞只读。
- [ ] **M0-03 开发环境**：本机已安装 Xcode 27.1（27A9275），iOS 27.0 / iPhone 17 Pro 模拟器构建、启动与 27 项测试通过；`.venv` 已固定 `ib_async==2.1.0`。Gateway、账户与实际 API 配置仍待补充；Apple 步骤见 `../apps/trading-agent/README.md`。
- [ ] **M0-04 模拟环境**：准备 Paper 账户、行情权限、目标账户、本机 API、只读配置和固定非零 client ID；隔离实盘、保护凭据，不只靠端口判定环境。
- [ ] **M0-05 接入验证**：已实现 `ib_async` 只读适配层与离线连接故障测试；下一步联调 Gateway 和指定账户，验证 Mac/协议相容性、账户、行情、事件及基础期权数据。若恢复或维护成本不合适，再用相同场景比较 NautilusTrader。
- [ ] **M0-06 会话与外部订单**：实测 Mobile/TWS/Client Portal、同/不同用户名及 client ID/Master Client 的会话冲突、行情影响与订单可见性；区分读取/绑定/修改权限和历史窗口。
- [ ] **M0-07 技术决策**：已确定 PydanticAI Core＋官方 Harness、SQLite WAL 产品存储和通信 v1（JSON＋事件游标/SSE）；IBKR 采用独立 `ib_async` 薄适配，paper/live 必须显式配置、默认本机回环且执行关闭。云模型配置、真实 Gateway 接入、备份及外网访问继续验证。
- [ ] **M0-08 验证证据**：按通过/失败/未测记录版本、配置、步骤和脱敏结果；复用旧调研的接口、版本或代码前重新核对。
- [ ] **M0-09 认证周期**：验证每日 Auto restart、周末认证、IB Key、异常退出/主机重启和同用户名占用；记录时区及中断窗口，区分故障注入与真实跨周测试。

验收：模拟只读连接范围明确，认证失效可识别；文档核查、上游测试和账户实测分别记录，未通过项不宣称可用。

## 3. M1：服务基础与后续聊天

- [ ] **M1-01 工程骨架**：先建独立交易服务、配置模板、日志、依赖锁定与基础检查；聊天服务、SwiftUI 工程随后加入。
- [ ] **M1-02 领域模型**：先定义账户快照、完整合约、订单/成交、数据状态及稳定 ID；再补会话、工具、意图、审核、授权、任务、提醒和设备关联。
- [ ] **M1-03 存储**：迁移、事务、唯一约束、事件游标与备份；金额/数量使用明确精度，时间保存 UTC 及原始时区语义。
- [x] **M1-04 会话 API**：创建、搜索、命名、归档、历史、消息幂等、持久事件、SSE/增量补齐及协议版本已实现；见 `../packages/core-python/yolo_agents/api.py`、`../agents/trading-agent/runtime-python/tests/test_api.py` 和 `../packages/protocol/COMMUNICATION_V1.md`，本机真实 HTTP 测试通过。外网与真机另见 M5。
- [x] **M1-05 主 Agent**：已实现演示模式、官方 Core/Harness 适配、完整会话恢复、官方记忆工具、跨会话文本检索及压缩后原文召回，并通过真实 SDK 的离线模型验证。实际云端模型配置、中文召回和记忆决策质量仍待实测；无交易执行工具。
- [ ] **M1-06 权限**：分离查询、提案、确认、提交和任务授权；服务端强制校验，所有入口共用规则，Agent 不可改规则或直连券商。
- [ ] **M1-07 密钥与数据**：设备凭据用 Keychain、后端密钥受保护、日志脱敏；明确云端模型数据范围及供应商留存设置。
- [ ] **M1-08 macOS 界面（后续）**：SwiftUI 聊天、会话、流式回复、订单卡片、设置与健康状态；共享协议与内部框架解耦。
- [ ] **M1-09 生命周期**：交易服务独立启动/恢复，关闭 App 或重启聊天服务不终止它；区分可重试读取与须对账的交易动作。
- [ ] **M1-10 模拟依赖**：构造断线、过期/缺失数据、部分成交、拒单、乱序与提交超时，后续补审核失败场景。

验收：先交付独立服务与数据基础；聊天完成后再验收持久会话、多轮交互和重复请求去重。

## 4. M2：只读数据与对账

- [ ] **M2-01 适配接口**：连接、健康、账户、合约、行情、挂单/成交/持仓及事件；只读阶段关闭提交，M3 联调时仅按模拟盘开关开放。
- [ ] **M2-02 数据契约**：保存账户、币种、带方向数量/市值、来源、时间和完整性；缺失表示未知，不能变成零余额、空仓或默认资产。
- [ ] **M2-03 合约身份**：保存 conId/市场；期权保留标的、到期、行权价、Call/Put、乘数，已有期权持仓进入风险上下文。
- [ ] **M2-04 行情**：区分实时/延迟/冻结，定义 bid/ask/mid/last、来源时间、权限、限速和过期行为。
- [ ] **M2-05 对账**：启动、定期、重连查询结合事件，覆盖账户、挂单、成交、费用与持仓；按需恢复订阅，对账未完成禁止执行。
- [ ] **M2-06 标识与去重**：保存账户/conId、clientId/orderId、permId、成交标识映射；处理重复、乱序、迟到、更正及部分成交，防止重复计账。
- [ ] **M2-07 外部订单**：区分本系统/外部/来源未知，纳入占用但不自动绑定、修改或撤销；官方端操作后在已验证范围内收敛。
- [ ] **M2-08 历史缺口**：区分当前状态与完整历史；缺口明确未知，评估报表补充，内部修正不得冒充真实成交。
- [ ] **M2-09 聊天查询（后续）**：接账户/持仓/挂单/报价查询，展示数据时间与不可用原因；模型摘要不作账本。
- [ ] **M2-10 健康状态**：区分连接异常、重连、人工认证、对账中和数据就绪；端口可连不等于券商可交易，记录状态变化并提供告警入口。

验收：指定模拟账户只读、官方端操作同步和断线重连对账通过；失效可见、历史缺口保留、外部订单不被接管。

## 5. M3：审核与模拟盘订单

- [ ] **M3-01 订单意图**：完整账户/合约、方向、数量、类型、价格、TIF、时段及理由；歧义或缺字段返回待补充。
- [ ] **M3-02 硬规则**：权限、支持矩阵、数据完整/新鲜、购买力、持仓/挂单占用、限额、报价、时段及重复/冲突/未知请求。
- [ ] **M3-03 AI 审核**：APPROVE/REJECT/NEEDS_CONFIRMATION、证据和有效期；不可用、非法、过期不算通过，不覆盖硬规则。
- [ ] **M3-04 确认**：Mac 展示订单及风险，确认绑定版本/内容与授权范围；关键字段改变后重审和确认。
- [ ] **M3-05 提交前复核**：刷新状态、检查授权/审核、重跑规则；账户级串行或额度预留防止并发超限。
- [ ] **M3-06 环境与开关**：模拟/实盘隔离，实盘开关与账户/操作授权双重约束；暂停执行、撤销任务授权和撤销挂单分别处理。
- [ ] **M3-07 状态与幂等**：意图、授权、幂等键先落库再发单；覆盖提交中、未知、接受、部分成交、成交、拒单、取消及竞争事件。
- [ ] **M3-08 未知恢复**：覆盖券商已接单而本地未确认/落库的窗口；先查询，无法判定则保持未知并阻止相关重复执行。
- [ ] **M3-09 审计**：串联消息、订单版本、快照、模型/规则版本、审核、授权、请求与券商事件，回写执行进展。
- [ ] **M3-10 模拟盘验收**：限价单、超限/旧数据拦截、重复确认、部分成交、拒单、撤单竞争及超时恢复，保留可复现记录。

验收：没有有效审核/授权不得提交；直接调用业务接口也不能绕过规则，未知结果不触发盲目重发。

## 6. M4：定时订单

- [ ] **M4-01 任务与预授权**：原始指令、订单、账户/合约、时区、目标时间/窗口、过期、金额/数量/价格边界、取消条件、审核和幂等键。
- [ ] **M4-02 时间语义**：交易日历、节假日、夏令时重复/不存在时刻、盘前盘后、晚启动及过期；未授权不顺延。
- [ ] **M4-03 调度状态**：持久化领取、锁/租约、恢复和重复唤醒去重；任务与券商状态分开，覆盖未知/过期/取消。
- [ ] **M4-04 到点重审**：刷新连接、行情、账户、持仓、挂单及市场，重跑 AI/硬规则；授权有效且窗口内才进入统一入口。
- [ ] **M4-05 异常通知**：拒绝、待确认、认证失效、数据/模型/网络异常不提交；记录通知，未知结果转对账。
- [ ] **M4-06 任务管理**：查看、暂停、取消、修改后重审/授权，遵守设备权限，处理取消计划与券商已接单的竞争。
- [ ] **M4-07 券商侧定时**：验证订单支持、托管位置、修改/撤销和授权差异；独立验收前不启用，首版先做 Mac 到点重审。
- [ ] **M4-08 乘机前检查**：汇总任务、电源/休眠、网络、服务、行情、通知及会话；标记跨每日重启/周末认证的窗口和检查时间，不承诺登录后固定有效七天。
- [ ] **M4-09 故障验收**：App 关闭、手机离线、服务/网关重启、重复唤醒、提交后崩溃、授权撤销及过期；锁过期不等于允许重发未知订单。

验收：客户端离线不终止任务；过期不补发，认证失效暂停，实际成交以券商为准。

- [x] **M5-04 Apple 界面首版**：SwiftUI macOS / iOS 聊天、会话和健康状态已实现；模拟器构建/启动与真实 Keychain、SDK 通信测试通过。订单结果、提醒、完整 UI 交互及真机另行验收。
- [ ] **M5-05 监控条件**：股票/完整期权合约的高于、低于、上穿、下穿，包含口径、时段、冷却、一次/重复、暂停及过期。
- [ ] **M5-06 监控恢复**：持久化条件/触发状态，处理限额、断流、旧报价、重连跨阈值与重复事件，失效可见。
- [ ] **M5-07 通知**：选择通道（如 APNs），记录关联会话、去重、投递/失败，验证手机非前台提醒。

## 8. M6：部署与实盘门槛

- [ ] **M6-01 运维**：安装、启动、升级/回滚、迁移、Gateway 认证及安全远程桌面步骤，实测休眠与主机重启。
- [ ] **M6-02 监测**：服务/模型/券商、行情、对账、任务、未知订单、通知失败及磁盘，认证告警有处置入口。
- [ ] **M6-03 备份恢复**：保护数据库、配置及密钥，演练任务/审计/设备恢复；旧备份恢复后先对账，防止重复执行。
- [ ] **M6-04 稳定性**：约定负载/时长，测 CPU/内存、磁盘、恢复时间、限速、模型耗时/费用，设置保留策略；覆盖每日重启和真实跨周认证。
- [ ] **M6-05 故障回归**：覆盖重复/并发、未知结果、部分成交/拒单/撤单竞争、乱序、旧数据、官方端登录/人工操作、模型失败、进程/主机重启、时间边界及 iOS/通知；区分构造测试与账户实测。
- [ ] **M6-06 实盘范围**：明确账户、标的、类型、金额/敞口/当日限额、不支持操作及停用方法，由用户确认开放范围。
- [ ] **M6-07 受限实盘**：按确认范围验证立即/定时订单、人工订单同步与恢复；异常关闭新执行并对账，模拟盘不等于实盘成交保证。

验收：必要故障与恢复证据齐全，权限可撤销，可恢复运行但不重复下单。
