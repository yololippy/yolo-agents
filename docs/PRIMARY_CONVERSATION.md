# 主会话与自动上下文压缩

状态：已实现（2026-11-02）

## 目标

Trading Agent 采用“一个长期主会话＋多个任务会话”的产品形态：

- 每个 Agent、每个授权主体只有一个主会话。它用于持续交流、承接长期偏好和日常事务。
- 启动 Mac/iOS App 时默认打开主会话；App 从后台恢复时保留用户正在查看的会话，不强制跳转。
- “新会话”继续创建普通任务会话，用于隔离临时研究、调试或专项交易讨论。
- 主会话可以重命名，但不能归档；普通任务会话仍可归档。
- 产品聊天记录、订单账本和券商事实完整保留。上下文压缩只改变下一次模型调用携带的上下文，不删除产品消息，也不能替代订单或账户事实。

## 身份与迁移

产品数据库使用 `primary_conversations` 映射表，而不是在会话行上增加可随意切换的布尔值：

```text
primary_conversations
- owner_scope       # Agent 内部生成的不可逆主体摘要
- conversation_id  # 唯一主会话
- created_at
```

`owner_scope` 不保存邮箱、账号 ID 或令牌。ChatGPT Provider 模式把本机用户作用域与当前授权主体组合后再做 SHA-256；未登录状态使用独立作用域。因此不同授权账号的主会话和 Harness 数据空间互不冒充。

升级旧数据库时不批量改写历史。首次读取会话列表时，服务端按以下顺序惰性迁移：

1. 若当前主体已有映射，直接返回该主会话。
2. 否则选择最近更新、未归档、尚未属于其他主体且与当前 Runtime 状态兼容的会话。
3. 没有兼容会话时创建标题为“主会话”的新会话。

映射建立后保持稳定。服务端拒绝归档任何已映射的主会话，客户端同时隐藏该操作；重命名不改变映射。

## API 与客户端行为

`GET /v1/conversations` 返回：

```json
{
  "conversations": [],
  "primary_conversation_id": "UUID"
}
```

客户端把 `primary_conversation_id` 与离线快照一起保存。进程冷启动时仅恢复并选择这个 ID；若旧缓存尚无该字段，等待首次服务端同步后选择主会话，不再猜测“最近会话”就是主会话。用户在一次运行中切到任务会话后，断线重连和前后台切换都保留当前选择。

会话列表以“主会话”徽标标识映射对象。“新会话”按钮只创建普通任务会话。

## 自动上下文压缩

Harness Conversation 是模型上下文的权威状态；产品消息表是用户可见历史的权威状态。两者不得互相冒充。

当前采用 `TieredCompaction(target_fraction=0.60)`：

1. 先清理较旧且体积较大的工具返回，保留最近 3 对工具调用/结果。
2. 仍超过模型上下文窗口 60% 时执行增量总结，保留最近 20 条消息、用户消息和工具收据。

总结使用 Harness 的结构化摘要，保留目标、决定、产物、当前状态、下一步和阻塞。长期记忆仍由每个 Agent/授权主体自己的 Memory 保存；跨会话查找由 Conversation Search 完成。订单授权、持仓、行情、挂单和成交必须实时读取受控业务工具，不能从摘要或记忆推断。

## 边界

- 本次只实现 Trading Agent；共享协议和 Swift 组件保持其他 Agent 将来可复用，但不扩展 B Agent 产品功能。
- 当前不提供“删除并重建主会话”按钮。需要该能力时必须设计显式迁移与确认，不得把普通会话静默提升为主会话。
- 搜索过滤可能不包含主会话，但响应仍返回稳定的 `primary_conversation_id`；客户端不得因此改变映射。
