# Yolo Agents 开发协作

只由 `main` 协调本仓库的开发会话。开始协调前读取根目录 [AGENTS.md](../../../AGENTS.md) 和 [TODO.md](../../../docs/TODO.md)；涉及产品范围或总体架构时再读取 [项目大纲](../../../docs/PROJECT_OUTLINE.md)，涉及 PydanticAI、记忆或历史检索时再读取 [Agent 方案](../../../docs/RESEARCH_PYDANTICAI.md)。用户最新指令优先，根目录 AGENTS 中的多 Agent 复用边界必须保留。

## 主会话与本地状态

- 只有标题精确为 `main` 且工作目录为 `/Users/yololippy/project/yolo-agents` 的当前会话可以担任主会话；其他会话不得自行改名取得权限。
- main 是唯一可以创建、派遣、等待、读取和管理开发会话的会话，也是唯一负责跨模块协调、结果集成、根目录 TODO 更新、Git 操作和用户总汇报的会话。
- 非 main 会话不得联系 main 或其他开发会话，不得创建、派遣、等待、读取或管理其他 Agent，也不得继续分派任务；只执行 main 直接派发的任务，并在自己的最终回复中报告。
- 用户已授权 main 在当前开发范围内复用现有角色会话，或在没有合适活动会话时按需创建专项开发会话；这不扩大用户已授权的产品范围。
- 归档表示会话已经退役。main 不查询、读取、复用或取消归档会话；没有合适的活动会话时直接新建。
- 会话 ID 只记录在 Git 忽略的 `.agents/runtime/trading-agent-coordination/team.local.md`。该文件只是活动会话索引，不是授权来源；缺失时创建，记录失效时删除。实际标题、状态和工作目录以活动会话列表及会话详情为准。

项目代码依赖可以直接安装，Python 优先使用仓库 `.venv`。安装完整 Xcode、IB Gateway、远程网络客户端等独立软件时再请用户操作；常规开发、测试和可逆操作自主推进，但不得绕过系统或服务的访问限制。

## 角色与文件归属

这里的 `Agent` 角色是 Codex 开发会话；产品 Agent 是仓库中的 `trading-agent`、`b-agent` 等运行时和客户端，二者不得混淆。

| 会话 | 负责内容 | 默认可写范围（开发获授权后） |
| --- | --- | --- |
| main | 拆分任务、协调接口、集成、验收、用户沟通、Git 操作 | 根目录文档、`.agents/`、`docs/` 及统一配置 |
| Ibkr | 券商接入、账户事实、订单、对账与交易规则 | `agents/trading-agent/runtime-python/` 中由 main 指定的 IBKR 与交易私有文件 |
| Agent | Agent 运行时、会话、记忆、受控工具、服务端协议实现 | `packages/core-python/`、`packages/protocol/`，以及 main 明确指定的 Agent 私有文件 |
| iOS | 共享 Swift SDK/UI、Trading Agent 的 Mac/iPhone 客户端和 Xcode 工程 | `packages/sdk-swift/`、`packages/ui-swift/`、`apps/trading-agent/` |
| 按需会话 | 协议、共享 Package、专项排障或其他明确任务 | 由 main 派活时明确；不得与其他正在工作的会话重叠写入同一文件 |

- IBKR 与 Agent 后端可能同时涉及 `agents/trading-agent/runtime-python/`。main 必须按具体文件或子模块分配写入权，不能只按顶层目录分工；同一文件同时只由一个会话修改。
- 非 main 会话可以只读其他模块了解上下文；需要跨越写入范围时，只在完成回复中提出，由 main 重新分配负责人。
- `Ibkr`、`Agent`、`iOS` 是当前已有角色，不是永久封闭的角色清单。新任务确有独立职责时，main 可以创建标题清晰且唯一的专项会话。

## 多 Agent 复用与当前范围

- 派活前先判断改动属于共享协议、领域无关运行时、Swift SDK、通用 UI，还是某个产品 Agent 的私有能力。可复用部分放入职责匹配的 `packages/`，通过配置、能力声明或依赖注入适配，不得在共享层写死 `trading-agent`。
- Agent 私有策略、账户数据、券商集成、权限和产品入口保留在对应的 `agents/<agent-name>/` 与 `apps/<agent-name>/`；凭据、缓存和运行状态按产品 Agent 身份隔离。
- 默认只为 `trading-agent` 接入和验收新功能。除非用户明确要求，不修改、扩展、构建、联调或验收 `b-agent`；未来可复用性通过共享接口和测试证明。
- 共享接口发生变化时，由 main 先协调使用方和文件归属，再决定修改顺序；不得让多个会话并发改同一个 manifest、协议文件或公共接口。

## 派活与收取结果

1. main 先核对自己的标题和工作目录，再读取本地活动会话登记；只通过活动会话列表核对真实标题、状态和目录，不查询归档列表。
2. 优先复用职责匹配的活动会话。没有合适会话且任务确有需要时，main 在本仓库同一工作树创建标题清晰、唯一的会话，不创建额外 checkout，并把活动信息写入本地登记。
3. 每次派活必须说明目标、允许写入的文件或目录、依赖接口、验收方式、允许动作，并重申不得跨会话通信、继续分派或执行 Git 操作。只读分析任务必须明确不改文件。
4. 所有会话共享同一工作目录和工作树。main 在派活前检查现有未提交改动，避免覆盖用户或其他会话的工作；并发任务只写互不重叠的文件。
5. main 使用等待能力收取完成或需要关注的状态，必要时读取会话详情。非 main 会话只在自己的回复中报告，不主动向其他会话回传。
6. 完成回复必须列出修改文件、实现结果、实际执行的验证及结果、未验证部分、需要 main 集成的事项。不得把测试或构建通过描述为模拟器启动、真机安装或真实服务验收通过。
7. main 审查完整差异、完成必要的集成验证、按实际进度更新 TODO，再向用户总汇报。非 main 会话不得暂存、commit、push、切换分支或清理工作树；用户要求提交时由 main 使用 `$commit-workflow`。

本 skill 只管理开发协作，不创建应用内多 Agent 编排、额度监控、定时唤醒、自动续跑或重复的进度账本。任务进度继续使用现有 TODO 和活动会话上下文。
