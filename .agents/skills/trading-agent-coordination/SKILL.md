# Trading Agent 协作与额度恢复

## 已确定的工作方式

用户只与 `main` 对话，由 main 给同仓库的 `Ibkr`、`Agent`、`iOS` 三个已有会话指派工作、收取结果并整合。用户已经授权这种协调方式，也授权在套餐额度恢复后向这些会话发送“继续”，在该范围内无需重复询问。

用户已澄清：项目代码依赖可以直接安装，Python 优先使用仓库 `.venv`；安装完整 Xcode、IB Gateway、远程网络客户端等独立软件时才叫用户。其他常规开发、测试和可逆操作自主推进，不重复确认，不绕过系统或服务的访问限制。

读取 [项目大纲](../../../PROJECT_OUTLINE.md)、[现有 TODO](../../../TODO.md) 和 [Agent 方案](../../../RESEARCH_PYDANTICAI.md)。IBKR 路线是 IB Gateway／TWS API 的独立 Python 薄服务，优先验证 ib_async；主 Agent 使用 PydanticAI Core 与官方 Harness 组件。用户已确定的选型不因旧文档仍写“暂缓”而重新要求确认。当前任务和用户最新指令优先。

这里管理的是 Codex 开发会话的套餐额度，区别于应用内模型 API 的计费、IBKR 登录周期和交易定时任务。

## 派活与收取结果

- 用 `list_threads` 按项目和工作目录识别现有会话，保留实际返回的标题；标题不唯一时再核实。不要为这些已有角色创建替代会话。
- `Ibkr` 负责券商接入、账户事实、订单、对账与交易规则；`Agent` 负责 PydanticAI、会话、记忆与受控工具；`iOS` 负责 Apple 客户端和同步体验。按实际任务明确接口、交付、验证与文件归属，三者共享工作目录，避免同时修改同一文件。
- 通过 `send_message_to_thread` 向授权的会话发出具体工作指令；用 `wait_threads` 读取结果并跟踪后续变化，需要细节时再读会话。main 负责集成验证和向用户报告；不要求对方主动向 main 发消息。
- 不增加用于中断恢复的业务进度文件；沿用会话上下文和已有项目文档。正常开发如需更新现有 TODO，按当前任务处理。
- 套餐恢复后，main 向 `Ibkr`、`Agent`、`iOS` 各发送一次正文为“继续”的消息即可。恢复流程不要求先重新扫描进度或重新拆任务；实际返回的阻塞与结果在后续正常协调中处理。

## 独立额度监控

使用仓库已有的 [bin/codex-quota-watch.py](../../../bin/codex-quota-watch.py)，参数和运行时边界见 [使用说明](../../../bin/README.md)。不要用消耗模型额度的循环代替外部脚本检查。

1. 在进入实际开发、准备派活时启动监控。只要求编写脚本、测试或完善这个 skill 时不启动常驻监控，也不发送开发指令。Mac 开机、联网、App 运行是用户已确认可满足的条件。
2. 真实验证脚本能在预期运行时唤醒当前 main 并保留其跨会话工具，再启用 `--continue-thread`。当前只验证过真实只读额度查询与模拟续跑；桌面原运行时的唤醒链路尚未实测。独立 stdio 服务不等于桌面原运行时，共享接口必须是已验证的标准 app-server 控制 socket，不能把内部 IPC 或 app-tools socket 当作该接口，也不绕过其访问检查。
3. 正式监控使用仓库的 `bin/start-codex-quota-watch.py <MAIN_THREAD_ID>`。运行状态固定在仓库根目录的 `runtime/codex-quota-watch/`，该目录整体被 Git 忽略；停止使用 `bin/stop-codex-quota-watch.py`，不另建业务恢复账本。
4. 每次额度查询取得明确结果或错误记录。仅服务端明确允许使用才视为恢复；缺失数据、网络错误和预计重置时间到点都不证明恢复。脚本的查询/等待不调用模型，真实续跑仍使用套餐额度，不购买额度或更换计费方式。
5. 每次先观察到受限，再观察到恢复，脚本向 main 发送一次“继续”，等待真实轮次结果。仍明确限额就等待重试；成功后重新等待下一次受限，不因持续可用而重复发送。脚本不直接向三个工作会话发消息，由 main 负责转发。
6. 结果不明、非额度错误或需要人工处理时，监控继续查询，但自动发送进入暂停状态。先说明日志中的实际原因；处理并核实先前执行结果后再重启监控，不盲目补发，不自动同意审批。

## 何时停止

- **正常情况一直监控到整个已授权开发任务完成，或用户明确叫停。** 一次 main 回复结束、一次额度恢复、某个工作会话空闲，均不代表整个任务已完成。
- 整体任务完成后，main 运行仓库的 `bin/stop-codex-quota-watch.py`。用户叫停时同样使用该脚本；终端 Ctrl-C／SIGTERM 可立即停止进程。停止文件只是一个控制信号，不保存任务进度。
- 等待检查间隔时，脚本最多约一秒后响应停止文件；正在续跑时，正常停止文件让当前轮次结束后再退出，避免打断该轮。启动前若停止文件已存在，脚本直接退出；新一轮工作使用新的唯一停止路径。
- 保留脚本锁和防重复发送行为。监控没有启动、只有只读检查、自动发送暂停和真实续跑已验证是不同状态，向用户准确说明。

修改监控逻辑后运行 `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s bin/tests -v`。测试用模拟服务覆盖多次耗尽/恢复、重复抑制、停止信号、超时和失败；未获准进行真实续跑测试时只做真实只读查询。
