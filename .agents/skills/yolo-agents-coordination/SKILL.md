# Yolo Agents 开发协作

开始协调前读取根目录 [AGENTS.md](../../../AGENTS.md) 和 [TODO.md](../../../docs/TODO.md)；涉及总体架构时再读取 [项目大纲](../../../docs/PROJECT_OUTLINE.md)。用户最新指令和根目录范围规则优先。

## 会话层级

- 标题精确为 `main` 且工作目录为 `/Users/yololippy/project/yolo-agents` 的会话是仓库总协调者，可调配所有产品主会话和开发会话，负责跨产品冲突、共享层归属、最终集成、Git 操作和用户总汇报。
- `main-trade` 负责 YoloTrade 的任务拆分、产品内派发、审阅和验收；`main-beni` 对 YoloBeni 承担同样职责。产品主会话不得执行 Git 操作，不得管理另一产品的会话或私有文件。
- 其他开发会话只执行直接派发的任务，不继续派发，不联系其他会话，不执行 Git 操作。
- `main` 可以直接派发任何会话，也可以把产品范围交给对应产品主会话；产品主会话完成后向 `main` 报告，由 `main` 统一集成。

会话 ID 只记录在 Git 忽略的 `.agents/runtime/yolo-agents-coordination/team.local.md`。登记按 `main`、产品主会话、共享会话和产品开发会话分类；实际标题、状态与工作目录以活动会话列表为准。

## 路由与文件归属

派活前判断任务属于共享能力、YoloTrade 私有能力还是 YoloBeni 私有能力，并读取对应说明：

- 修改 `packages/` 或跨产品接口时读取 [共享层](references/shared.md)。
- 修改 YoloTrade 时读取 [YoloTrade](references/yolo-trade.md)。
- 修改 YoloBeni 时读取 [YoloBeni](references/yolo-beni.md)。

同一文件同一时间只能有一个写入会话。每个共享任务还必须有一个产品主会话或 `main` 作为唯一所有者；另一个产品需要相同共享文件时，由 `main` 决定顺序，不能并发修改。共享能力不得写死产品身份、目录、端口或私有业务规则。

## 派发与集成

1. 协调者先核对标题、工作目录、活动会话登记和未提交改动；保留用户及其他会话的现有修改。
2. 优先复用职责匹配的活动会话；没有合适会话且用户授权创建时，再在同一工作树创建职责清晰的开发会话。
3. 派活必须写明目标、允许写入的文件或目录、依赖接口、验收方式和允许动作，并重申不得跨会话通信、继续派发或执行 Git 操作。
4. 并发任务只能写入互不重叠的文件。公共 manifest、协议和接口由 `main` 指定单一负责人并安排修改顺序。
5. 完成报告必须列出修改文件、实现结果、实际验证、未验证部分和集成事项。产品主会话先审阅自己的范围，再交给 `main`。
6. `main` 审查完整差异，执行必要的跨产品回归和构建，更新 TODO；只有 `main` 可以暂存、提交、推送、切换分支或向用户作最终完成汇报。

项目依赖可以直接安装，Python 优先使用仓库 `.venv`。安装完整 Xcode、券商客户端或远程网络软件时再请用户操作；不得绕过系统或服务访问限制。

本 Skill 只管理开发协作，不创建产品内多 Agent 编排、额度监控、定时唤醒或重复进度账本。
