# Yolo Agents 开发协作

开始协调前读取根目录 [AGENTS.md](../../../AGENTS.md) 和 [ROADMAP.md](../../../docs/ROADMAP.md)；涉及总体架构时再读取 [架构](../../../docs/ARCHITECTURE.md)。用户最新指令和根目录范围规则优先。

## 会话层级

- `main`、`main-trade`、`main-beni` 是三个具备同等功能的主会话，都可以规划和实施任务、管理直属开发会话、修改当前任务需要的仓库文件、验收、执行 Git 操作并直接向用户汇报。
- 本 Skill 中的“开发会话”专指左侧栏可见、可独立打开和长期保留的会话级 Agent。仓库开发不得使用当前会话内部的临时子 Agent 代替，不得将其登记为开发会话或用其承担派发任务。
- 标题精确为 `main` 且工作目录属于 yolo-agents 任一 Git worktree 的会话具有全仓调配视角，可以调用两个产品主会话和全部开发会话。
- `main-trade` 默认聚焦 YoloTrade，`main-beni` 默认聚焦 YoloBeni；产品名称只表示主要上下文，不构成文件、共享层或 Git 权限限制。
- `main-trade` 和 `main-beni` 只能调用各自直属的普通开发会话，不得通过跨会话工具调用、发消息、派发、等待、读取或移交给 `main` 或另一个 `main-xxx`。需要跨主会话协调时，由用户分别沟通，或由 `main` 主动调配。
- 其他开发会话只执行直接派发的任务，不继续派发，不联系其他会话，不执行 Git 操作。
- 用户可以分别在三个主会话中直接下达开发、验收和 commit 指令；每个主会话独立闭环，不把可自行完成的工作转交给另一个主会话。

会话 ID 只记录在 Git 忽略的 `.agents/runtime/yolo-agents-coordination/team.local.md`。登记按 `main`、产品主会话、共享会话和产品开发会话分类；实际标题、状态与工作目录以活动会话列表为准。

## 开发与测试会话权限

用户已选择本仓库所有直属开发、测试会话使用 **Full Access**：`sandbox_mode = "danger-full-access"`、`approval_policy = "never"`。创建、复用或恢复会话时，由主会话通过受支持的会话配置接口实际设置并核对权限，同时把工作目录设为派发的准确 worktree；不能只在任务文字中要求 Full Access，也不能假定新会话继承父会话权限。

若应用的创建/消息工具没有权限参数，先创建左侧栏可见的独立会话，初始任务仅等待主会话设置权限，不读写文件、不执行工具。确认初始化轮次结束后，通过官方 CLI 在该会话中派发任务：

```sh
codex exec -C <准确worktree> --sandbox danger-full-access \
  -c approval_policy='"never"' --json resume <会话ID> - < <任务文件>
```

保留持久会话，不加 `--ephemeral`；用应用工具核对同一 ID、工作目录和产出，必要时打开该会话。CLI-only 新会话未必自动出现在侧栏，不得把它作为已登记开发会话；优先恢复应用已创建的会话。后续派活也显式传入权限参数，不回退到可能覆盖权限的默认消息配置。运行日志保存在忽略目录，ID 仍只登记在 `team.local.md`。

CLI 执行器运行期间，桌面应用可能把会话标为 `notLoaded`；用受管 CLI 进程、持续写入的事件日志及最终报告核对进度，不把应用未加载状态当成停工。CLI 退出后再从持久会话读取最终报告。协调者保留 CLI 进程句柄，不能断开后把尚在运行的任务误报为完成。

以当前 CLI 帮助和实际会话状态为准。已有运行中的审批请求不会仅因修改 Skill 自动消失；先通过受支持的中断流程结束旧轮次，确认不再执行，再在同一会话以 Full Access 恢复，不能并发启动同一会话的两个执行器。不要为更改权限重启整个应用或主机服务。

Full Access 只改变执行环境权限，不扩大任务范围：普通开发、测试会话仍不得跨会话派发或执行 Git 写操作；金融订单、对外发送、凭据隔离和其他必须由用户本人完成的授权规则照常保留。

## 路由与文件归属

派活前判断任务属于共享能力、YoloTrade 私有能力还是 YoloBeni 私有能力，并读取对应说明：

- 修改 `packages/` 或跨产品接口时读取 [共享层](references/shared.md)。
- 修改 YoloTrade 时读取 [YoloTrade](references/yolo-trade.md)。
- 修改 YoloBeni 时读取 [YoloBeni](references/yolo-beni.md)。

同一文件同一时间只能有一个写入会话。每个共享任务必须登记一个主会话作为唯一所有者；发现其他主会话正在修改相同文件时，不得跨主会话联系或抢占，必须保留现状并向用户报告冲突。共享能力不得写死产品身份、目录、端口或私有业务规则。

## Git 权限

- 三个主会话拥有相同的 Git 能力，可以处理当前用户任务授权范围内的任意仓库文件，不按产品目录或共享层限制 commit 权限。
- 三个主会话执行 commit 时都应使用提交工作流，按精确路径暂存、检查 cached diff，并保留其他会话的未提交内容；不得仅因工作树中存在其他改动就一并提交。
- 本仓库的 commit 不运行测试或构建。代码与对应测试放进同一 PR，先提交并创建 PR，再按 [PR 后置测试](../../../docs/PR_WORKFLOW.md) 派发独立测试会话；本仓库规则优先于通用提交技能中的测试时机。
- push、历史重写及其他外部或破坏性 Git 操作仍需用户明确授权。普通开发会话不得执行 Git 操作。

## 派发与集成

1. 协调者先核对标题、工作目录、活动会话登记和未提交改动；保留用户及其他会话的现有修改。
2. 优先复用职责匹配的活动会话；没有合适的活动会话时，在同一工作树创建职责清晰的左侧栏独立开发会话。已归档会话不恢复，也不因标题或职责匹配而重新启用。
3. 派活必须写明目标、允许写入的文件或目录、依赖接口、验收方式和允许动作，并重申普通开发会话不得跨会话通信、继续派发或执行 Git 操作。
4. 并发任务只能写入互不重叠的文件。当前主会话为公共 manifest、协议和接口指定单一负责人；如果所有权已属于另一个主会话，停止写入并向用户说明。
5. 完成报告必须列出修改文件、实现结果、实际验证、未验证部分和集成事项。三个主会话都可以独立完成差异审查、必要回归、TODO 更新、commit 和用户汇报。
6. `main` 可以主动检查和协调全仓；产品主会话不依赖 `main` 完成自己的工作，也不得主动调用 `main` 或另一个产品主会话。

## PR 测试会话

PR 创建后，主会话自动准备对应准确 head/base 的隔离 worktree，再派发最多三个左侧栏可见的测试会话。每个会话的任务写明 PR、head SHA、base SHA、产品、测试组、独立构建/报告目录和允许的清理范围。会话只执行固定测试入口并报告，不修代码、不执行 Git 写操作、不继续派发；只读 Git 版本核对可由入口执行。

主会话汇总 P0、Mac、Simulator 与双端真实 UI 对话/同步结果，合并前再次从官方 GitHub API 核对 head/base 和门禁。测试失败或版本变化时不合并，修复推送后重新测试。合并只使用 rebase，不 squash；合并授权必须来自用户，不从普通开发或 commit 请求推断。完整命令和报告契约以 [PR 流程](../../../docs/PR_WORKFLOW.md) 为准。

项目依赖可以直接安装，Python 优先使用仓库 `.venv`。安装完整 Xcode、券商客户端或远程网络软件时再请用户操作；不得绕过系统或服务访问限制。

本 Skill 只管理开发协作，不创建产品内多 Agent 编排、额度监控、定时唤醒或重复进度账本。
