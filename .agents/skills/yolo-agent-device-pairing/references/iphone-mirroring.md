# iPhone Mirroring 操作

仅在需要通过 Mac 代用户完成 iOS 配对时读取本文件。

## 启动与判断

1. 使用 `xcrun devicectl list devices` 发现实际连接的物理 iPhone；不要保存或写死 UDID。
2. 使用目标 App 的实际 Bundle ID 启动 App。
3. 打开 `iPhone Mirroring`，查询当前窗口的位置和尺寸，并截取当前画面检查所处页面。
4. 如果镜像尚未完成 Apple 自身的设备配对，或手机要求用户解锁，停止自动输入并只让用户完成该系统动作；完成后继续其余步骤。

## GUI 操作

- 每次根据当前窗口和截图定位控件。窗口可能移动、缩放或显示系统弹框，禁止复用历史绝对坐标。
- 优先通过可访问性元素操作；镜像画面没有可访问性子元素时，使用当前窗口坐标换算点击位置，并在每个状态变化后重新截图核对。
- 第一次点击网络字段可能触发 iOS 无线数据权限。选择“无线局域网与蜂窝网络”，不要选择“仅限无线局域网”或“不允许”。
- 服务地址从当前 Tailscale Serve 状态取得。使用 HTTPS 时不要打开“允许本地开发连接（未加密）”。
- iPhone Mirroring 的粘贴可能读取 iPhone 自身剪贴板，而不是刚设置的 Mac 剪贴板。服务地址、设备名称和配对码应聚焦字段后通过物理键盘事件直接输入；输入后截图核对地址，密码式配对码字段只核对长度和提交按钮状态，不回显秘密。
- 点击“配对此设备”后等待页面转换。不要因短暂“正在同步”重复提交同一个一次性配对码。

## 新配对码

当前 Host 的配对码保存在进程内存中，并在启动时写入其标准输出日志。没有可复用的有效码时：

1. 记录 Host 日志当前字节位置。
2. 仅重启目标 Agent 的用户级 LaunchAgent。
3. 等待健康端点恢复。
4. 只从记录位置之后的新增内容提取 `ios pairing code`，不得读取旧码充当新码。
5. 配对完成后不要在最终回复中重复展示仍有效的配对码；只报告成功状态。

若 Host 管理方式已改为支持不重启生成配对码，应优先使用新的受控入口，并同步更新本参考。

## 验收

- 手机已离开配对页并进入当前 Agent 的会话列表。
- 服务端设备表新增或保留一个未撤销的目标 iOS 设备，名称与本次输入一致。
- 健康端点的 `agent_id` 与目标 App 一致。
- Trading Agent 的 Broker 状态为 `connected_paper`、`ready=true`，不存在未完成对账阻塞。
- 未修改订单、未重启 IB Gateway、未把运行时秘密写入仓库。
